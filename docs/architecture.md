# Android architecture

The app reuses the native Kotlin client because it already implements pairing, permission discovery, encrypted storage, event streams and transcript parsing. Rewriting those systems in Android Views would discard tested behavior without adding a requested capability. Swift is the behavior reference for mobile navigation and added project pages; its source is not a runtime dependency.

## Ownership

- `core/` owns routes, capability policy, response parsing, transcript ordering, Markdown and state rules, with JVM tests.
- `app/Store.kt` owns the paired connection, projects, sessions and cache, and gates mutations.
- `app/Conversation.kt` owns each session's transcript and send state, shared by screen and notification callers.
- `app/Navigator.kt` owns the selected destination and navigation history; resizing changes presentation.
- `app/ui/` renders native Compose controls and calls named operations instead of building URLs.
- `app/src/main/kotlin/com/okanetsolutions/briareus/tokens/BriareusTokens.kt` is generated by the contracts repository and copied unchanged.

Pairing reads discovery and OpenAPI before persisting credentials. Projects and sessions refresh before the event stream resumes. Each conversation merges its transcript using the sequence cursor, so duplicate events do not append duplicate messages. Store identity checks discard responses from an old connection.

## Design comparison

Two independent candidates considered native Views with feature fragments and reuse of the Kotlin Compose app. A separate review favored Compose on reused functionality, contract compatibility and maintenance cost. Both required native keyboard input and width-independent selection.

The selected design keeps the existing core/app boundary and adds a phone/tablet shell. It incorporates two corrections from the Views candidate: uncertain writes require a successful refresh before sending again, and navigation state must survive width changes instead of belonging to a pane's temporary layout.

The contract's 1024dp breakpoint and 268dp sidebar remain authoritative. On a narrow display, Android Back replaces a permanent sidebar. The bottom navigation follows Swift's Projects, Findings, Usage and Settings tabs. The board is read-only in this port, avoiding an unsafe immediate refresh after a GitHub Projects write.

## Verification boundaries

Core fixtures exercise the wire formats used by the new project screens, diff pagination and table copying. Existing tests cover TLS origin policy, credential headers, redirects, route permissions, transcript ordering and Markdown. Android compilation, lint and detekt check the app. These checks do not replace a physical device or a live server acceptance session.
